Démarrer : ton compte et ta clé pour modifier le site

Cette partie se fait une seule fois, avec Simon à côté de toi la première fois. Compte une demi-heure. Tout se fait dans le navigateur de ton téléphone : tu n'as rien à installer.

Les écrans de GitHub changent parfois un peu : si un bouton n'a pas exactement le même nom, cherche le plus ressemblant.

Étape 1 : créer ton compte GitHub

  1. Ouvre github.com et appuie sur Sign up (s'inscrire).
  2. Donne une adresse e-mail à toi, un mot de passe solide et un nom d'utilisateur (celui que tu veux : il n'apparaît pas sur ton site, ton site garde son adresse).
  3. GitHub t'envoie un code par e-mail : recopie-le.
  4. Note ton mot de passe sur papier et garde-le chez toi. Ne l'écris jamais sur le site ni dans un message.

Étape 2 : activer la double sécurité par SMS

Cette protection demande un code reçu par SMS à chaque connexion depuis un nouvel appareil. Elle protège ton compte et ton site.

  1. Connectée à GitHub, appuie sur ta photo (en haut), puis Settings.
  2. Appuie sur Password and authentication, puis Enable two-factor authentication.
  3. Choisis SMS / Text message (pas « Authenticator app » : cela t'obligerait à installer une application).
  4. Entre ton numéro de téléphone (la France est prise en charge), puis le code reçu par SMS.
  5. GitHub te donne des codes de secours : recopie-les sur papier et garde-les avec ton mot de passe. Ils servent si tu perds ton téléphone.

Étape 3 : rejoindre l'organisation du site

Le site appartient à l'organisation oriana-valenza sur GitHub. Simon t'y invite en tant que propriétaire (Owner).

  1. Tu reçois un e-mail « You've been invited to join the oriana-valenza organization ».
  2. Ouvre-le et appuie sur Join oriana-valenza.
  3. Vérifie : tu dois voir l'organisation dans la liste de tes organisations (Settings, puis Organizations).
Pour Simon : l'invitation se fait dans l'organisation, People, Invite member, rôle Owner. Dans Settings, Authentication security, activer l'obligation de la double sécurité pour tous les membres.

Étape 4 : créer ta clé (le « jeton »)

Le jeton est une clé secrète qui permet à l'éditeur de publier sur ton site. Il ne marche que pour ce site et il expire au bout d'un an.

  1. Dans GitHub, appuie sur ta photo, Settings, puis tout en bas du menu Developer settings.
  2. Personal access tokens, puis Fine-grained tokens, puis Generate new token.
  3. Token name : écris par exemple « Mon site ».
  4. Expiration : choisis une date dans un an. Note cette date, tu la donneras à l'éditeur.
  5. Resource owner : choisis oriana-valenza (l'organisation) et pas ton nom.
  6. Repository access : Only select repositories, puis choisis oriana-valenza.github.io.
  7. Permissions, Repository permissions : mets
    • Contents : Read and write (lire et écrire) ;
    • Actions : Read-only ;
    • Checks : Read-only.
      (Metadata passe tout seul en lecture : c'est normal.) Ne mets rien d'autre.
  8. Appuie sur Generate token. Si GitHub dit que la demande doit être approuvée, dis-le à Simon : il l'approuve dans l'organisation (Settings, Personal access tokens).
  9. Le jeton s'affiche une seule fois (une longue suite de lettres). Copie-le tout de suite avec l'icône de copie.
Attention : le jeton est comme un mot de passe. Ne l'envoie par message à personne, ne le prends pas en photo, ne l'écris jamais sur le site. Si tu l'as montré par erreur : va dans la liste de tes jetons et appuie sur Delete (supprimer), puis recommence l'étape 4.

Étape 5 : te connecter à l'éditeur

  1. Ouvre oriana-valenza.github.io/admin/ et ajoute la page à tes favoris pour la retrouver.
  2. Colle le jeton dans Mon jeton.
  3. Entre la date d'expiration notée à l'étape 4.
  4. Appuie sur Me connecter. Tu vois le menu « Que veux-tu modifier ? » : c'est bon.

L'éditeur te prévient un mois avant l'expiration : il faudra alors refaire l'étape 4 (un nouveau jeton) et le coller à la place de l'ancien (Me déconnecter, puis te reconnecter).

Si tu changes de téléphone

Refais simplement l'étape 5 avec le même jeton, ou l'étape 4 pour un nouveau. Rien d'autre n'est lié à ton téléphone.

Utiliser l'éditeur : modifier, ajouter, annuler

L'éditeur est à l'adresse oriana-valenza.github.io/admin/. Rien n'est publié tant que tu n'appuies pas sur Publier. Tes modifications sont gardées dans ton téléphone en attendant.

Modifier un texte

  1. Dans le menu, choisis la page (Musique, Écriture, Audiovisuel, Services, Oriana…).
  2. Chaque texte a deux cases : Français et English. Modifie les deux.
  3. Appuie sur Voir ce que je publie (en bas) : tu vois la liste de tes changements, avant et après.
  4. Appuie sur Publier. Les étapes s'affichent. Ton site est à jour dans 1 à 3 minutes : recharge la page du site pour voir.

Ajouter quelque chose (un livre, un film, une offre, une étape de parcours)

  1. Ouvre la page concernée et descends jusqu'à la liste (par exemple « Livres »).
  2. Appuie sur + Ajouter un livre (ou film, offre, étape…). Une fiche vide apparaît.
  3. Remplis le titre, le texte, la photo et la description de la photo (obligatoire : une phrase qui dit ce qu'on voit, pour les personnes qui ne la voient pas).
  4. Les boutons Monter et Descendre changent l'ordre. Supprimer retire la fiche (tant que tu n'as pas publié, tu peux tout remettre avec « Remettre cette page comme en ligne »).

Ajouter une photo

  1. Dans la fiche, appuie sur Choisir une photo et prends-la dans ta galerie. L'éditeur la réduit tout seul pour que le site reste rapide.
  2. Ne ferme pas la page avant d'avoir publié : une photo choisie mais pas encore publiée est perdue si la page est rechargée.
  3. Les photos d'autres personnes : n'ajoute que celles dont tu as l'accord.

Remplir un « Bientôt » : liens, vidéos, dates

Plusieurs endroits du site affichent « Bientôt » parce que le contenu n'existe pas encore : les boutons YouTube et Spotify (page Musique, « Écouter et suivre »), le lecteur des clips, la date, le lieu et les billets du concert, les paroles de chaque titre, Instagram et Facebook (en bas de toutes les pages). Quand le contenu existe, tu le remplis et le « Bientôt » disparaît tout seul.

  • Menu, Liens : chaque ligne dit où le lien apparaît. Colle l'adresse complète de la vidéo ou du site (elle commence par https://). Pour YouTube, l'éditeur retrouve seul l'identifiant de la vidéo. Laisse vide si tu n'as pas encore le lien.
  • Vidéo d'un film (page Audiovisuel) : dans la fiche du film, colle l'adresse YouTube dans Vidéo YouTube de ce film. Un bouton apparaît sous le texte ; vide, aucun bouton.
  • Paroles : page Musique, fiche du titre, case Paroles.
  • Concerts : page Musique, bloc En concert, + Ajouter un concert (date, lieu, billetterie). Plusieurs dates possibles ; « Bientôt » disparaît dès qu'il y en a une.
  • Clips : page Musique, bloc Clips, + Ajouter un clip (titre et adresse de la vidéo YouTube) : un lecteur par clip.
  • Autres réseaux (TikTok…) : menu Liens, + Ajouter un lien (réseau, site…) (nom et adresse en https://). Il apparaît en bas de toutes les pages.
  • Quand le contenu arrive, relis aussi les phrases autour (par exemple « Les clips de RVL sont en préparation » ou « Adresse de contact à venir ») : elles ne se changent pas toutes seules.

Annuler

  • Avant de publier : sur la page concernée, appuie sur Remettre cette page comme en ligne.
  • Après avoir publié : dans le menu, appuie sur Annuler ma dernière publication. Le site revient à ce qu'il était juste avant (c'est valable sur le téléphone qui a publié).
  • Revenir plus loin en arrière : dans le menu, appuie sur Voir les anciennes versions du site. Chaque ligne est une publication avec sa date. Appuie sur Revenir à cette version : le site redevient comme il était juste après elle. Tu peux ensuite annuler ce retour avec Annuler ma dernière publication. Les modifications que tu n'avais pas publiées sont mises de côté.

Renouveler le jeton (avant sa date d'expiration)

Un mois avant l'expiration, l'éditeur t'affiche un bandeau. Crée un nouveau jeton (étape 4 de « Démarrer »), puis dans le menu appuie sur Renouveler mon jeton, colle-le et indique sa nouvelle date d'expiration. Tes modifications en attente sont gardées.

Numéros de téléphone et e-mails

Tout ce qui est écrit sur le site est public. Si tu écris un numéro ou une adresse e-mail, l'éditeur te demande de confirmer que c'est voulu (par exemple un contact professionnel) et à quoi il sert. Une fois confirmé, il est accepté pour la suite. N'écris jamais ton numéro personnel ou ton adresse personnelle si tu ne veux pas qu'ils soient publics.

Si une IA gratuite t'aide à écrire

Tu peux demander à une IA gratuite (ChatGPT, Gemini, Claude…) de t'aider à rédiger, reformuler, traduire ou corriger. L'IA ne touche jamais au site : c'est toi qui copies son texte dans les cases de l'éditeur, et l'éditeur vérifie avant de publier.

  1. Ouvre une nouvelle conversation avec l'IA.
  2. Copie le modèle de demande ci-dessous (bouton Copier sur la page d'aide) et colle-le.
  3. Réponds à ses questions, puis relis chaque phrase : l'IA peut se tromper ou inventer. Toi seule sais ce qui est vrai.
Ne donne jamais à une IA : ton jeton, un mot de passe, un numéro de téléphone, une adresse e-mail ou une adresse postale. Ces conversations peuvent être gardées.

Débrayage : si le contrôle de sécurité empêche tout (pour la personne qui dépanne)

Le site a un contrôle automatique (un « workflow » GitHub) qui vérifie chaque publication. Si, un jour, il refuse tout alors qu'il n'y a pas de raison, qu'il est cassé ou que Simon n'est plus là, on peut le désactiver. L'éditeur le détecte et publie ensuite sans l'attendre. Il continue de vérifier les textes dans ton téléphone (balises, mots de passe, contacts à confirmer), mais le contrôle complet (par exemple le texte des PDF) n'a plus lieu.

À faire dans le navigateur, connectée à GitHub, sur la page du dépôt oriana-valenza/oriana-valenza.github.io. Choisis une des deux méthodes.

Méthode A : supprimer le fichier du contrôle

  1. Ouvre le dossier .github, puis workflows, puis le fichier controle.yml.
  2. Appuie sur les trois points en haut à droite, puis Delete file, puis Commit changes.
  3. Pour le remettre plus tard : dans l'historique du dépôt (History du dossier), retrouve la version précédente du fichier et recrée-le.

Méthode B : désactiver les Actions du dépôt

  1. Dépôt, Settings, Actions, General.
  2. Sous Actions permissions, choisis Disable actions, puis Save.
  3. Pour les remettre : même écran, Allow all actions.

Si une règle de branche exigeait le contrôle (il n'y en a aucune aujourd'hui) : dépôt, Settings, Rules (ou Branches), supprime la règle qui exige le contrôle « controle » avant de fusionner.

Après le débrayage, publie un petit texte pour vérifier : l'éditeur doit afficher « Contrôle automatique absent ou désactivé… » puis « Publié ».
